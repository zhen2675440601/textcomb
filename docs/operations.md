# 部署与运维

## 上线前

- 将 `TEXTCOMB_PUBLIC_ORIGIN` 设为唯一 HTTPS 站点源，例如 `https://textcomb.example.com`，不得带路径。
- 将 `TEXTCOMB_SECURE_COOKIES` 设为 `true`。
- 使用密码管理系统保存 PostgreSQL 密码和 32 字节主密钥；不得提交 `.env`。
- 主密钥丢失后模型密钥无法恢复。轮换主密钥需要先实现逐条重加密流程，不能直接替换。
- 只开放 Caddy 端口。PostgreSQL、API、Worker 和假模型不得直接暴露到互联网。
- 为宿主机、容器镜像、TLS、数据库备份和安全更新建立责任人。

## 健康与指标

- `/healthz`：进程存活。
- `/readyz`：数据库可查询。
- `/metrics`：Prometheus 文本格式。不得把该端点公开给未授权互联网用户。

结构化日志只应出现请求 ID、用户 ID、任务 ID、阶段、耗时、用量和错误码。正文、问题片段、密码、Cookie、模型密钥和完整提示词禁止进入日志。

建议告警：

- 队列最老等待时间持续超过 10 分钟；
- 任务失败率或模型 429/5xx 重试率突增；
- 租约恢复次数非零；
- 任务 P95 超过 60 分钟或逼近 120 分钟强制超时；
- 清理任务连续失败；
- PostgreSQL 或共享存储剩余空间不足 20%。

## 数据生命周期

- 上传时原文件和失败重试数据的过期时间为 24 小时。
- 成功、取消或用户删除会立即清除原文件与完整正文；文件系统删除失败时保留待清理路径并每小时重试。
- 报告、问题片段和 PDF 默认 180 天后删除。
- 用户主动删除报告会同步删除问题与反馈；任务只保留不含正文的最小状态元数据并标记 `expired`。
- 匿名统计只能保留类别与反馈结果，不能保留原文片段。

## 备份与恢复

备份 PostgreSQL、账户数据和仍在保留期内的报告卷。不要备份 `uploads/`、`tmp/` 或数据库 `documents.extracted_text`；它们属于短期处理数据。备份任务应在删除策略执行后再生成，长期备份中不得重新出现已删除原文。

恢复演练至少验证：迁移可前滚、会话可失效、报告 JSON/Markdown/PDF 一致、过期清理继续工作。恢复环境必须使用与备份匹配的主密钥。

## 版本升级

1. 备份数据库与报告卷。
2. 拉取固定版本镜像，不使用未锁定的 `latest`。
3. 单独运行 `textcomb-cli migrate`。
4. 先启动 API 并检查 `/readyz`，再启动 Worker，最后切换 Caddy。
5. 观察失败率、队列和租约恢复；若应用回退，数据库迁移仍保持前滚兼容。
