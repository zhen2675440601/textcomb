# TextComb 路线图

本文件描述产品阶段和退出条件；具体实现任务、负责人和实时状态以 GitHub Issues、Pull Requests 和项目状态为准。没有明确负责人、验收标准和资源的事项不视为已排期。

## 当前阶段：开源 MVP 基线

仓库已经具备可部署的开源 MVP 代码基线，重点工作从“搭建功能”转向“验证质量、可靠性和可维护性”。代码基线不等于质量认证，参考模型门槛仍需独立私有评测验证。

### 基线能力

- Rust API、Worker、管理 CLI 和 Vue 3 工作台。
- PostgreSQL 任务队列、租约恢复、取消、失败块重试和异步进度。
- 直接粘贴正文、TXT、DOCX、文字型 PDF 提取及来源定位。
- 双轮 AI 候选/复核、统一报告对象、JSON/Markdown/PDF 导出。
- 登录、管理员创建用户、可修改的 BYOK 模型配置、数据清理和安全边界。
- Docker Compose、假模型、评测工具、测试样例和开发文档。

## 阶段一：MVP 质量加固

### 重点

- 建立至少 50 篇双人标注、第三人裁决的私有评测集，并逐步扩展到 1000 个已裁决问题。
- 完善 TXT、DOCX、PDF、长文切块、位置映射、结构化输出修复和重叠去重测试。
- 验证 5 万字文章的异步进度、取消、失败重试、超时和数据清理。
- 完成密钥加密、权限隔离、日志脱敏、文件限制、ZIP 炸弹和 PDF 解析安全测试。
- 对参考模型配置连续运行评测，记录提示词、依据库和模型版本。

### 退出条件

- 三类输入和拒绝场景均有明确结果。
- 10 个可控假模型并发任务不重复领取、不串报告、内存保持上限。
- 参考模型连续两轮达到正式准确率 90%、正式加疑似召回率 90%、疑似准确率 70%。
- JSON、Markdown、PDF 内容一致，问题位置可以回到原始来源。

## 阶段二：开源 Beta

### 重点

- 完成 10 任务并发的负载、故障恢复和数据库租约测试。
- 提供中文部署、升级、备份、故障排查和贡献文档。
- 稳定容器镜像、CI、健康检查、Prometheus 指标和清理任务。
- 完善 Issue/PR 模板、贡献者流程、评测程序和外部反馈闭环。
- 发布 AGPL 社区版；质量声明只针对锁定的参考模型配置。

### 退出条件

- 新主机可以依据文档完成启动、迁移、创建用户、配置模型和跑通端到端流程。
- 失败恢复、取消、删除和报告过期策略经过自动化测试。
- 外部贡献者能够在不接触私有评测集和真实文章的情况下运行测试。

## 阶段三：托管商业版（明确后置）

- 公开账号密码注册、邮件找回和服务端模型额度。
- 按篇展示、按字符数内部计量的不可变积分账本。
- 微信支付、支付通知、退款/返还和对账。
- 隐私政策、服务条款、第三方模型披露和数据处理专项法律审查。
- 价格只在完成真实模型成本采样后确定，不提前写死人民币价格。

## 阶段四：微信小程序（商业流程稳定后）

- uni-app Vue 3＋TypeScript，共享 OpenAPI 客户端和领域类型。
- 微信登录绑定、上传、进度、历史报告、逐条反馈和支付。
- 小程序只调用现有 API；计费、分析和报告生成继续留在 Rust 后端。
- 不提供全文在线编辑和客户端核心业务逻辑。

## 优先级规则

- **P0**：数据安全、权限隔离、原文删除、报告正确性、任务幂等和严重崩溃。
- **P1**：输入解析、位置映射、长文稳定性、模型重试、进度和导出一致性。
- **P2**：筛选体验、反馈体验、部署便利性、监控和贡献者体验。
- **P3**：商业化、小程序、非首版检查类型和额外模型协议。

## 不纳入当前排期

OCR、自动改写、事实核查、论文格式、全文一致性、专业术语保证、支付、小程序和任意模型质量承诺，除非维护者明确更新 `PROJECT.md` 和本路线图。
