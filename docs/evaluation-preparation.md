# 私有评测准备与验收

本流程用于准备评测和交付人工审核，不将探索试跑或 AI 生成的标注认定为质量认证。私有目录应位于仓库外，或使用已被 Git 与 Docker 忽略的 `private-evaluation/`。不要将全文、裁决标注、模型密钥或人工意见放进 Issue、CI 制品或公开 PR。

## 样本与来源

首轮至少 50 篇不同的完整文章；同一文章的错误副本、片段、不同文件格式或多次运行不计为不同文章。建议如下分层，具体来源与配额由维护者在开始前冻结：

| 场景 | 500–2,000 字符 | 2,001–10,000 字符 | 10,001–50,000 字符 | 合计 |
| --- | ---: | ---: | ---: | ---: |
| 通用文章 | 10 | 15 | 5 | 30 |
| 学术论文 | 0 | 5 | 5 | 10 |
| 财报/商业报告 | 0 | 5 | 5 | 10 |

学术、财务样本必须包含实际目标文体，百科文章只能作探索性场景探针。20 万字符上限、加密/扫描/损坏 PDF、限流与取消另作工程测试，不混入自然文章质量分数。错误植入副本用于定位和已知构式回归，单独报告；不能替代自然错误或低误报样本。覆盖全部问题类别和病句子类，但不强求每篇出现错误；保留经人工确认无错误的全文。

每篇私有 manifest 至少记录：不含路径的文档 ID、完整正文的 SHA-256、正文字符数、来源版本/链接、授权依据、场景、长度层、原文件格式、提取器版本、标注状态。保存提取后不可变正文；只在明确记录的分析副本中规范换行/空白。文章版本更新后需重新核对哈希、位置和标注，不覆盖上一轮证据。

## 三人标注交接

1. A、B 两名不同的人工标注者分别取得全文、统一规则和各自的空白 JSONL；独立完成前不得查看对方标注或模型预测。记录人员标识、完成时间和正文哈希，不把预填空数组视为审核完毕。
2. 两人按 Unicode 字符的左闭右开范围标注自然错误；记录病句子类、是否依赖作者意图、保护区、建议是否保留原意及理由。标注格式见 `label.schema.json`，其他审核属性存放私有专项表。
3. C 是不同于 A、B 的第三位人工裁决者。逐项处理分歧，确认同一位置唯一类别；保存分歧记录和裁决理由，产生最终 Gold。
4. 将“无错误”文章也交给 C 确认。裁决完成的文档才进入冻结集；逐步积累 1,000 个裁决问题是样本建设目标，不通过重复复制同一构式凑数。

维护者应核对三人记录和授权；AI 可以辅助整理差异，不能替代人员身份与独立审阅。尚无这些记录时，将结果明确标为“探索评测”。

## 两轮验收

冻结正文/Gold 哈希、服务商协议、实际模型版本、初检/复核模型、温度 0、提示词、依据库指纹、分析器提交、场景与字数范围。仅同名模型不足以确认服务商未更换模型版本。

每轮为全部 50 篇保存完整 ReportV1、状态、耗时、服务商用量和配置快照。失败、缺失、取消或不完整报告单独计入覆盖表并阻止该轮验收，先排查而非删除样本。每轮运行 `textcomb-eval`，核对正文哈希与位置，并人工评审建议保留原意、保护区误报及疑似专项表。

同一冻结配置连续两轮分别达到正式准确率 ≥90%、正式加疑似召回率 ≥90%、疑似准确率 ≥70%；分段建议单列。分场景、长度、类别和病句子类同时展示样本量，不以总体平均掩盖空白或失败子集。没有疑似预测时其准确率为 0，不能自动视为达标。

公开摘要仅包含数据集版本/哈希、样本数与分层、配置版本、两轮聚合指标、失败率、耗时/用量、建议审核结论及限制，不公开全文和逐处标注。维护者完成发布审阅后，才可为明确范围的固定配置激活参考认证；自定义模型继续显示“未经验证”。
