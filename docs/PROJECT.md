# TextComb 项目说明

## 一句话定位

文梳（TextComb）是面向中国大陆简体中文作者的开源辅助校对工具，重点发现错字、标点和基础病句，并把问题定位、原因、修改建议和置信度整理成可审核报告。

## 要解决的问题

自媒体作者、论文作者和新闻稿作者在文章完成后通常没有足够时间人工校稿；语法问题尤其容易被作者自己忽略。TextComb 的目标是缩短初步校对时间，提供可解释的候选问题，而不是替作者做最终判断。

## 目标用户

1. 首要用户：自媒体作者和公众号文章作者。
2. 次要用户：论文作者、新闻稿作者和其他中文文章作者。
3. 早期验证对象：维护者身边的朋友和真实写作者。

## 产品承诺

- 对中国大陆简体中文提供基础辅助校对，不宣称替代人工编辑。
- 每个问题尽量提供原文位置、问题片段、问题原因、修改建议和置信度。
- 报告可打开与问题位置一致的“分析原文”；DOCX 与 PDF 显示提取后的文字正文，不复现原文件排版。
- 低置信度结果标记为“疑似错误”，由作者自行审核，不强制修改原文。
- 模型、提示词、依据库和分析器版本记录在报告中；未经私有评测的自定义模型显示为“未经验证”。
- 报告中的位置必须能够回到原始页/行或段落/句子；定位失败的模型候选不得进入报告。

## 首版检查范围

### 正式检查类别

- 错字。
- 标点符号。
- 基础病句：语序不当、搭配不当、成分残缺、成分赘余、句式杂糅、表意不明、不合逻辑、关联词语使用不当、用词不当。

### 疑似建议

- 主题发生变化但可能没有分段。
- 缺少已授权权威依据的成语、典故和词义问题。
- 模型置信度不足以进入正式问题区的候选。

## 输入与输出

- 输入：直接粘贴的正文（按 UTF-8 TXT 处理）、UTF-8/GB18030 TXT、文字型 DOCX、文字型 PDF。
- 限制：单文件不超过 20 MiB，提取正文不超过 5 万字。
- 扫描版、加密或损坏 PDF 首版直接拒绝，不实现 OCR。
- 输出：在线问题报告、版本化 JSON、Markdown 和 PDF。
- 不输出自动修改后的原文，不提供全文重写入口。

## 质量目标与边界

- 发布门槛：参考模型配置的正式问题准确率、正式加疑似召回率、疑似准确率逐步达到 90% / 90% / 70%。
- 98% 整体准确率和召回率是成熟版目标，不是当前版本承诺。
- “误报小于 10%”只对锁定的参考模型、提示词、依据库和评测集讨论；不能对任意用户自带模型保证。
- 模型负责候选发现和复核，服务器负责解析、定位、结构校验、证据白名单、置信度分层和去重。
- 所有建议仅供作者参考，最终修改决定由作者完成。

## 设计原则

1. **可审核**：每个结果都要能解释、定位和追溯。
2. **高召回后复核**：先发现候选，再统一复核，避免逐条模型调用。
3. **不伪造确定性**：没有可靠规则或授权依据时进入疑似区，不伪造引用。
4. **隐私优先**：不记录完整提示词、密码或模型密钥；成功后清除原始上传文件，仅将提取正文与报告关联保留至报告过期或用户删除，取消和用户删除后立即清除正文。
5. **开源可替换**：首版支持 OpenAI Responses、OpenAI Compatible 和 Anthropic，并通过统一 Provider 接口保留后续扩展点。
6. **先做可部署单体**：Rust API/Worker/CLI 与 PostgreSQL 组成模块化单体，不提前拆分微服务。

## 明确不做

首版不做 OCR、自动改写、事实核查、论文格式检查、全文一致性、专业术语保证、支付、商业额度、微信小程序和复杂在线编辑。商业版或小程序必须复用现有 API 与领域类型，不能把核心逻辑复制到客户端。

## 成功标准

- 作者可以上传一篇不超过 5 万字的支持格式文章，并看到可持续更新的异步进度。
- 任务支持完成、失败、取消和失败块重试，不重复调用或生成不完整的“成功”报告。
- 报告可筛选、反馈和导出，JSON、Markdown、PDF 来自同一规范化报告对象。
- 参考模型在私有评测集上连续达到发布门槛后，才可以在发布说明中声明质量验证配置。
